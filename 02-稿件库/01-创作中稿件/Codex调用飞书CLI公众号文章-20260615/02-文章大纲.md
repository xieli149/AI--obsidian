# Codex 调用飞书 CLI：文章大纲

## 文章定位

这不是一篇飞书 API 大全，也不是一篇命令行教程。

这篇文章面向已经在用 Codex、但还没有把飞书资料接进 AI 工作流的运营人、内容人和轻技术用户。核心价值是让读者理解：Codex 不是只能写代码，它可以通过 `lark-cli` 读取、搜索、同步和更新飞书里的工作资料，把飞书从“资料存放处”变成“AI 可以调用的工作现场”。

## 核心观点

让 Codex 调用飞书 CLI，真正重要的不是多会敲命令，而是把三件事理顺：

1. 飞书负责存资料和协作。
2. `lark-cli` 负责把飞书能力变成命令。
3. Codex 负责读规则、跑命令、整理结果、写回本地或飞书。

一句话：飞书是资料库，CLI 是接口，Codex 是执行助手。

## 推荐标题

主标题：

AI 不只会写代码：我让 Codex 直接调用飞书 CLI，资料整理快了很多

备选标题：

- Codex 还能这样用：直接读取飞书文档、整理资料、生成稿件
- 飞书资料太散？让 Codex 调 `lark-cli` 帮你跑起来
- 运营人别只把 AI 当聊天框：Codex + 飞书 CLI 才像工作流
- 当 Codex 接上飞书，你的文档就不只是文档了

## 结构

1. 开头：很多人用飞书存资料，但 AI 写作时还在复制粘贴。
2. 先给结论：Codex + `lark-cli` 的三层关系。
3. 能做什么：读取文档、搜索资料、导出文件、同步文件夹、写回文档。
4. 怎么开始：先确认安装、登录、读 skill、再跑命令。
5. 最常用命令卡：`doctor`、`auth status`、`docs +fetch`、`drive +search`、`drive +sync`。
6. 适合运营人的 3 个场景：资料调研、会议纪要整理、公众号素材归档。
7. 注意事项：权限、范围、先 dry-run、重要文档不要直接覆盖。
8. 结尾：不要急着学全部 API，先让 Codex 跑通一个真实任务。
