# 运营必备AI工具推荐11：hatch-pet，给 Codex 换一只自己的电子宠物

![封面图](images-final/cover-final.png)

最近我发现一个很有意思的小功能：Codex 里可以放一只自己的电子宠物。

听起来好像只是可爱。

但真正用起来以后，你会发现它不只是装饰。

当 AI 在等你确认、正在执行任务、遇到失败、帮你 review 的时候，如果旁边有一只小东西跟着变状态，整个工作台会更像“有人在陪你干活”。

这件事本身不复杂。

真正容易卡住的是：很多人以为自定义宠物就是换一张图片。

但恰恰相反。

**Codex 的宠物不是一张图，而是一套能被应用识别的动画文件。**

所以这篇就用小白能看懂的方式，把 `hatch-pet` 这件事讲清楚：怎么安装、怎么定制、最后生成出来的宠物模型到底放在哪里。

## 先说结论：hatch-pet 是一个“宠物生产线”

`hatch-pet` 不是一个现成宠物。

它更像一条生产线：

- 你告诉它：我想要什么样的宠物。
- 它帮你准备生成任务。
- 它让图像模型生成基础形象和不同动作。
- 它再用脚本把这些动作整理成 Codex 能吃的格式。
- 最后产出一个可以放进本地 Codex 的宠物包。

也就是说，你不是在“下载一个皮肤”。

你是在让 AI 帮你孵化一只属于自己的工作台小助手。

![流程图](images-final/workflow-final.png)

## 第一步：先把 hatch-pet 装到 Codex 里

如果你已经在用 Codex，安装方式很简单。

在 Codex 里输入：

```text
$skill-installer hatch-pet
```

装好以后，重启 Codex。

一般情况下，它会被安装到这个位置：

```text
~/.codex/skills/hatch-pet
```

你可以把这个目录理解成：

“以后 Codex 只要看到你想做宠物，就知道该调用哪套流程。”

如果安装时遇到网络、证书、下载失败之类的问题，也不要慌。

你只要对 Codex 说：

```text
安装 hatch-pet 时下载失败了，请改用 git 方式安装。
```

这类问题通常不是你操作错了，而是本地网络或证书环境没有配好。

**小白不要在这里硬查报错。让 AI 换安装方式，往往更快。**

## 第二步：搞清楚 skill 和宠物文件不是一回事

这里很容易混。

`hatch-pet` 是 skill，是“生产线”。

真正被 Codex 读取的宠物，是另外一组文件。

最终宠物会放在：

```text
~/.codex/pets/<你的宠物名字>/
```

里面通常只有两个关键文件：

```text
pet.json
spritesheet.webp
```

`pet.json` 像一张身份证，告诉 Codex：

- 这个宠物的 id 是什么
- 显示名字叫什么
- 简短描述是什么
- 动画图集文件在哪里

`spritesheet.webp` 才是真正的动画图。

你可以把它理解成一整张“动作大拼图”。

Codex 会按固定位置去读取里面的每一个小格子，然后播放成动画。

## 第三步：自定义宠物，重点不是“画得多精细”

很多人第一次做自定义宠物，会忍不住把提示词写得特别复杂：

赛博、发光、很多道具、很多小细节、最好还有文字和 logo。

但宠物不是海报。

它最后要缩在一个很小的格子里，每一格只有 `192x208`。

所以真正重要的是：

- 轮廓要清楚
- 表情要稳定
- 颜色要统一
- 道具不要太碎
- 不要有文字、logo、漂浮特效
- 每个动作看起来还是同一只宠物

`hatch-pet` 支持很多风格，比如：

- `pixel`：像素风
- `plush`：毛绒玩具风
- `clay`：黏土风
- `sticker`：贴纸风
- `flat-vector`：扁平矢量风
- `3d-toy`：3D 玩具风
- `painterly`：绘本风
- `brand-inspired`：品牌灵感风
- `auto`：让它自动判断

如果你没有特别明确的想法，我建议先用 `auto`。

因为新手最容易犯的错，不是风格不够特别，而是风格太复杂，最后缩小以后什么都看不清。

## 第四步：它会生成 9 行动作，不是随便动一动

Codex 读取宠物动画时，格式是固定的。

整张图集尺寸是：

```text
1536 x 1872
```

它由 `8` 列、`9` 行组成。

每一个小格子是：

```text
192 x 208
```

9 行分别对应不同状态：

| 状态 | 它在表达什么 |
| --- | --- |
| `idle` | 平时安静待着，轻微呼吸或眨眼 |
| `running-right` | 向右移动 |
| `running-left` | 向左移动 |
| `waving` | 打招呼 |
| `jumping` | 跳起 |
| `failed` | 任务失败或出错 |
| `waiting` | 等你确认、等你输入 |
| `running` | 正在处理任务，不是字面意义的跑步 |
| `review` | 正在检查、思考、审阅 |

![图集说明](images-final/atlas-final.png)

这也是为什么我不建议你自己手工拼。

因为你不只是要画一只宠物。

你还要让它在 9 种状态里保持同一个样子，同时保证尺寸、透明背景、动作帧都对。

**自定义宠物最难的地方，不是生成图片，而是让每一格都能被 Codex 正确读取。**

## 第五步：你可以这样告诉 Codex 你想要什么

如果你只是想试一只自己的宠物，可以直接复制下面这段话：

```text
我想用 hatch-pet 给 Codex 做一只自定义宠物。

宠物名字：请叫它「小工友」
风格：毛绒玩具风，干净、可爱、不要复杂细节
形象：一只圆圆的小助手，主色是浅绿色和奶白色，表情认真但不严肃
动作要求：按 Codex 的 9 行状态完整生成
注意：不要文字，不要 logo，不要漂浮特效，不要背景，最后帮我做 QA 并打包到 ~/.codex/pets
```

如果你已经有参考图，可以加一句：

```text
参考图在：/你的/图片/路径/reference.png，请尽量保留它的颜色和整体气质，但不要直接复制文字或 logo。
```

如果你想做品牌感宠物，可以说：

```text
请先做轻量品牌调研，只提取颜色、气质、产品隐喻，不要复制 logo、标语、界面截图或可识别文字。
```

这句话很重要。

因为品牌灵感可以用，但 logo 和文字不要乱复制。

否则做出来的不是可爱的工作台宠物，而是一个容易出问题的商标贴纸。

![提示词清单](images-final/checklist-final.png)

## 第六步：真正执行时，Codex 会做这些事

你不用记住所有脚本。

但你最好知道它大概在做什么。

正常流程是这样：

1. 准备一个运行目录。
2. 写入宠物名称、描述、风格和参考图。
3. 生成基础形象，也就是这只宠物的“标准长相”。
4. 基于标准长相，生成 9 行动作。
5. 把每行动作拆成单帧。
6. 合成 `spritesheet.webp`。
7. 校验尺寸、透明背景、空白格、动作帧。
8. 生成 contact sheet 和 GIF 预览，方便检查。
9. 打包成 `pet.json` 和 `spritesheet.webp`。

对小白理解就是：

你只负责说清楚想要什么。

Codex 负责把它变成应用能识别的“标准宠物包”。

## 如果你想看命令，大概长这样

这一段不是让你手敲。

只是让你知道它背后不是玄学。

```bash
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/hatch-pet"

python "$SKILL_DIR/scripts/prepare_pet_run.py" \
  --pet-name "小工友" \
  --description "一只陪你工作的 Codex 小助手" \
  --pet-notes "毛绒玩具风，浅绿色和奶白色，圆润、认真、不要文字和 logo" \
  --style-preset plush \
  --output-dir "/你的/运行目录"
```

等所有图像生成和 QA 都通过后，再打包到：

```text
~/.codex/pets/小工友/
```

里面至少应该有：

```text
pet.json
spritesheet.webp
```

如果这两个文件缺一个，Codex 就很可能读不到它。

如果图片尺寸不对，或者背景不是透明的，也可能显示异常。

## 最后上线前，我建议你检查 5 件事

1. 宠物缩小以后还看得清吗？
2. 9 行动作是不是同一只宠物？
3. `idle` 状态是不是安静，不会一直大幅晃动？
4. `waiting`、`running`、`review` 三个状态能不能区分？
5. `pet.json` 和 `spritesheet.webp` 是否在同一个宠物目录里？

这几件事比“第一眼惊艳”更重要。

因为宠物是长期挂在工作台上的。

它不需要像海报一样复杂。

它需要稳定、清楚、舒服。

## 我为什么觉得这个小功能值得折腾

坦白说，电子宠物不是刚需。

没有它，Codex 也照样能干活。

但它会让 AI 工作台多一点“可感知的状态”。

AI 正在执行，宠物会动。

AI 卡住等你确认，宠物会等。

AI review，宠物会进入检查状态。

这种反馈很小。

但对长期使用工具的人来说，它会让整个环境更像自己的。

**工具被你改造成自己的样子以后，你会更愿意每天打开它。**

所以我不把它看成单纯的可爱挂件。

它更像是 AI 工作台里的一个小仪表盘。

你不用一开始就做得很复杂。

先装好 `hatch-pet`。

再用一句清楚的提示词，做一只简单、稳定、能看清的小宠物。

等你跑通一次流程以后，再慢慢调风格、调表情、调品牌感。

先让它活起来。

后面再让它长得更像你。
